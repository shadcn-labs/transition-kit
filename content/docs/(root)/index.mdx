**transition-kit** provides theme transitions, page transitions and animated UI components for React. Built on React 19.3's [`<ViewTransition>`](https://react.dev/reference/react/ViewTransition), `startTransition` and `addTransitionType`, and designed to work seamlessly with the [shadcn CLI](https://ui.shadcn.com).

## Philosophy

transition-kit follows the shadcn model for motion: copy-paste code you own, with zero lock-in and defaults that work immediately.

View transitions are often wired up by hand — `document.startViewTransition` calls scattered across event handlers, racing the framework's own rendering. transition-kit takes a different approach. **React owns the transition**: every theme change and navigation runs inside `startTransition`, tagged with `addTransitionType`, and React decides what to snapshot and when. There is no animation library and no runtime beyond React itself.

Each style is a few lines of plain CSS. The shadcn CLI merges it into your `globals.css`, where you can tweak timing, easing and keyframes like any other stylesheet.

## Three groups

- **[Theme](/docs/components/theme):** `ThemeTransitionProvider` and `useThemeTransition` own the light/dark theme and animate every change. Pick a style such as circle reveal or wipe, or drop in one of the ready-made toggles.
- **[Page](/docs/components/page):** `<PageTransition>` animates between routes whenever its `id` changes, and `navigateWithTransition` runs any router's navigation as a React Transition, forward or back.
- **[UI](/docs/components/ui):** interactive components (tabs, carousel, kanban board and more) whose state changes glide, morph and slide with `<ViewTransition>`. They share the `ui/ui-transition` core: composable `tk-*` classes you can use in your own components.

Installing a style or component pulls in its core automatically.
